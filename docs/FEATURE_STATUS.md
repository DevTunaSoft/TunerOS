# Feature status — TunerOS

**Status snapshot: 2026-11-15 (latest green `main` run [43773518879](https://github.com/DevTunaSoft/TunerOS/actions/runs/43773518879) on `e1a99da`: Kotlin build, APK and Android 35 emulator QA PASS; main report 25 PASS, 0 FAIL, 0 BLOCKED, 12 NOT RUN, including the startup-recovery check; the external-storage dispatch [43769200236](https://github.com/DevTunaSoft/TunerOS/actions/runs/43769200236) on `9e7deb5` reports `external-recording-storage` PASS, with 26 PASS, 0 FAIL, 11 NOT RUN, and its picked-folder recording matches the served file byte for byte; physical Android TV and real DVR acceptance NOT RUN).** The emulator script exits non-zero when any isolated gate fails, so that green run also required the loopback import, Doze exact-alarm delivery, remote keys, rotation, recording, scheduled recording and startup re-arm gates to pass. These are synthetic emulator checks. They are not approval of real provider streams, USB/SD removal, reboot, or sustained physical-device memory. The optional public inputs are dispatch-only. On `4944e5f`, dispatch [43749178517](https://github.com/DevTunaSoft/TunerOS/actions/runs/43749178517) passed the public guide import (`channels=3 programs=36443`), three imports plus five idle minutes with one process kept alive (soak), and a guide memory peak of about 75 MiB total PSS. The same run rendered a first frame on 3 of 8 public-playlist streams; the other five failed with Media3 codes 2001, 2004 and 3003. The real provider with a login is not used, by decision. Foreground DVR teardown defers catalog close until the recording worker completes; actual service-destruction fault injection remains unverified.
