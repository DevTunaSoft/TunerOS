# Feature status — TunerOS

**Status snapshot: 2026-11-15 (latest green `main` run [43743155125](https://github.com/DevTunaSoft/TunerOS/actions/runs/43743155125) on `a9e2ec3`: Kotlin build, APK and Android 35 emulator QA PASS; main report 25 PASS, 0 FAIL, 0 BLOCKED, 12 NOT RUN; physical Android TV and real DVR acceptance NOT RUN).** The emulator script exits non-zero when any isolated gate fails, so that green run also required the loopback import, Doze exact-alarm delivery, remote keys, rotation, recording, scheduled recording and startup re-arm gates to pass. These are synthetic emulator checks. They are not approval of real provider streams, USB/SD removal, reboot, or sustained physical-device memory. The optional public guide import is dispatch-only. On the emulator it passed for a real public guide (`channels=3 programs=36443`) on the XMLTV fix branch. The latest dispatch run [43743187400](https://github.com/DevTunaSoft/TunerOS/actions/runs/43743187400) on `845e550` also passed every required gate, and one memory sample after the pass read about 66 MiB total PSS. The fix is a draft PR ([#3](https://github.com/DevTunaSoft/TunerOS/pull/3)) and is not yet merged. Foreground DVR teardown defers catalog close until the recording worker completes; actual service-destruction fault injection remains unverified.
